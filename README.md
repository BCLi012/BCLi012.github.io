# 静水深流 · 苹果风个人博客

一个极简苹果风格的个人博客站点：写代码，也写文字。

| 形态 | 地址 | 说明 |
|---|---|---|
| GitHub Pages（静态） | https://Bruce-C-L.github.io/ | 由本仓库直接托管，纯静态浏览 |
| 云端站点（完整） | https://apple-style-blog.app.workbuddy.link/ | 含数据库、登录、写作后台 |

## 功能

- **首页** — 个人 bio、渐变标语、最新文章、栏目入口
- **文章列表 / 详情** — 卡片式列表，详情页 Markdown 渲染（标题、引用、代码块、表格、图片）
- **标签分类** — 标签云、按标签筛选、分类栏目（文艺 / 随笔 / 技术 / 读书 / 生活）
- **关于页面** — 自我介绍与站点说明
- **后台管理** — 登录后可发布、编辑、删除文章（仅云端站点）
- **登录认证** — 邮箱密码登录、邮箱验证码登录、邮箱验证注册、忘记密码重置（仅云端站点）
- **图片与附件** — 编辑器内直接上传，自动插入正文（仅云端站点）

## 两种运行模式

代码是同一份，页面根据访问域名自动切换数据来源：

| | GitHub Pages / 本地预览 | 云端站点 |
|---|---|---|
| 文章来源 | 仓库内 `posts/` 的 Markdown 文件 | 云数据库 `posts` 表 |
| 阅读文章 | ✅ 完整可用 | ✅ |
| 登录 / 注册 | ❌ 不可用 | ✅ |
| 在线写作 / 上传 | ❌ 不可用 | ✅ |
| 访问 `#/admin` | 提示前往云端站点 | 写作后台 |

> **为什么 Pages 上不能用登录？** 云端服务会校验收访来源域名，只认已登记的云端站点域名。
> 因此静态托管环境下无法获得数据访问权限，改为直接读取仓库里的 Markdown。

## 技术栈

| 层 | 选型 |
|---|---|
| 页面 | 原生 HTML + CSS + JavaScript（无构建步骤，单页 hash 路由） |
| 样式 | 手写 CSS 设计系统，跟随系统深色模式，毛玻璃导航 |
| Markdown | marked + DOMPurify（渲染并消毒） |
| 数据（云端） | WorkBuddy 云数据库（PostgreSQL，行级安全策略） |
| 文件（云端） | WorkBuddy 云存储（图片 / 附件，签名链接） |
| 认证（云端） | WorkBuddy 云端账号体系（邮箱 + 密码 / 验证码） |

## 目录结构

```
.
├── index.html            # 页面骨架、导航与页脚
├── style.css             # 设计系统与全部样式
├── app.js                # 云端接入、双模式数据层、路由与各页面渲染
└── posts/                # 静态文章（GitHub Pages 使用）
    ├── manifest.json     # 文章清单与元数据
    └── *.md              # 各篇文章的 Markdown 正文
```

## 新增文章

**静态版（GitHub Pages）**：在 `posts/` 下新建 `xxx.md` 写正文，然后在 `posts/manifest.json`
的 `posts` 数组里加一条元数据（`id` / `title` / `category` / `tags` / `summary` / `created_at` / `file`），
提交推送即可。

**云端版**：在云端站点登录后进入写作后台，内容自动入库，无需改代码。

## 本地运行

无需构建，起一个静态服务器即可：

```bash
python3 -m http.server 8080 --bind 0.0.0.0
# 打开 http://localhost:8080
```

本地会以静态模式运行，可直接预览文章阅读体验。

## 数据与安全

云端文章存放在 `posts` 表：`id`、`owner_id`（作者，由数据库按登录身份自动填充）、`owner_name`、
`title`、`summary`、`content`、`category`、`tags`、`status`、`created_at`、`updated_at`。

安全策略：已发布文章所有人可读、草稿仅作者可见；新增 / 修改 / 删除均限定为文章作者本人。

正文中的图片和附件以 `cloud:<存储路径>` 占位保存，渲染时批量换取有时效的访问链接，
因此不会出现过期死链。

`app.js` 中的 `publishableKey` 是应用的公开标识，本身不携带任何权限 —— 服务端会校验请求来源域名，
只有登记过的站点域名才能访问数据，因此它可以安全地放在前端代码中。
